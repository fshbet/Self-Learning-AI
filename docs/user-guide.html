Knowledge Platform — User Guide

A self-updating, evidence-first knowledge base for any technical topic. This guide is for people who use the platform day to day; no programming is required for anything on this page.

What it is, in one minute

You give the platform a topic (Power BI is built in), a list of trusted websites, and optionally some search keywords. It then:

Collects pages→Extracts small, precise facts→Keeps a verbatim quote as evidence for each→ Scores & verifies them→Notices when pages change→Answers your questions with citations

Three rules make it trustworthy:

  • No evidence, no knowledge. A fact that cannot be traced to an exact quote in a source page is thrown away.
  • Nothing is silently overwritten. When two sources disagree, both are kept and the pair is shown to you to decide.
  • Answers only use stored knowledge. The assistant cites the items it used; if the knowledge base does not cover your question, it says so instead of guessing.

Start it up

Everything runs on your own machine. You need Docker Desktop, Ollama and the project folder. Open a terminal in the project folder:

  1. Start the database
    docker compose up -d postgres
  2. Start the platform (API, background worker and web app in one process)
    uv run kp serve
  3. Open the app at http://127.0.0.1:8010. The sidebar shows two green dots when the database and the local AI model (Ollama) are reachable.
First-time setup (only once): uv sync --extra dev, uv run kp db upgrade, uv run kp domains sync, and cd frontend && npm install && npm run build. The README has the full list.

Your first knowledge

  1. Pick the domain in the sidebar (Power BI).
  2. Go to Sources. You will see the built-in catalogue (Microsoft Learn, DAX Guide, SQLBI…). Press the download icon next to one source to crawl just that source, or press Run pipeline on the Dashboard to crawl all of them.
  3. Watch Pipeline. Crawling takes seconds per page; extraction is the slow part — roughly 20–30 seconds per page section on a mid-range GPU, because a local AI model reads every section.
  4. Open Knowledge. Items appear as they are extracted. Click any row to see its evidence.
Start small. A full crawl of all Power BI sources is several hundred pages and can take hours of GPU time. Use the max pages/source box on the Pipeline page (e.g. 10) for a first run, then let the platform grow the repository on its own schedule.

A tour of the screens

Dashboard

How much knowledge you have, how much of it is verified, open conflicts, documents, and what the AI model cost so far. Run pipeline starts a full crawl of the current domain.

Knowledge

Browse and filter every fact. Filter by status, topic, type, confidence; sort by recency or confidence. Click a row to open the detail drawer.

Search & Ask

Ask gives a written answer with numbered citations; Search lists matching items directly. Both use meaning-based and keyword search together.

Review

The queue of things the system will not decide alone: contradictions between sources and the lowest-confidence items. This is where a human keeps the knowledge honest.

Evaluation

Golden questions run against the knowledge base: accuracy, citation correctness, hallucination rate, regression detection and what to fix next.

Sources

The websites the platform is allowed to read, with trust level, permissions and crawl scope. Add your own URLs and keywords here.

Documents

Every page that was collected, its version, and how many facts came from it. Click to see the cleaned text the AI actually read.

Pipeline

Runs and their jobs (crawl, extract, discover). Failed jobs show the error and can be retried.

Domains

The installed topic plugins and their taxonomy, and the recipe for adding a new one.

Snapshots

Reproducible, hash-verified exports of a topic's knowledge for other AI systems, with AI-ready and human-readable files.

Settings

Which models do the work — local Ollama or an API provider — per role, with live model lists and tests.

Add your own URLs

Any documentation site, product manual, blog or reference page can be added to an existing topic without touching any files.

  1. Open Sources and find the card Add your own URL.
  2. Paste the URL. Give the page a name if you like (otherwise the website's name is used).
  3. Set Authority — how much you trust the site, 0–100. Official vendor documentation ≈ 95, a well-known expert site ≈ 80, a general blog ≈ 40. Authority feeds directly into every fact's confidence score.
  4. Set Pages and Depth. Depth 0 reads only that page; depth 1 also follows its links, and so on. The crawler never leaves the folder you gave it: for https://vendor.com/docs/manual/ it stays under /docs/manual/.
  5. Leave crawl now ticked and press Add. Progress appears on the Pipeline page; new facts show up in Knowledge with the source's name attached.

Sources you add are tagged user. They are kept when the plugin catalogue is re-synced, can be paused, re-crawled or removed with the bin icon (removing a source also removes the documents and facts that came from it). Built-in sources are tagged plugin and can be paused but not deleted here.

The platform is a polite reader: it obeys each site's robots.txt, identifies itself, waits between requests and backs off when a site asks it to. If a site forbids crawling, the source is marked BLOCKED and nothing is collected.

Add discovery keywords

Keywords are search phrases the platform uses to find new websites for a topic.

  1. On Sources, type a phrase into Discovery keywords (for example Power BI incremental refresh best practices) and press Add keyword.
  2. Press Discover sources. The platform searches the web for your keywords plus the plugin's built-in ones.
  3. Websites it has not seen before appear under Discovered candidates. Nothing is crawled until you press Approve — you stay in control of what is read.
Web discovery needs the optional local search engine: run docker compose --profile discovery up -d once. Without it the Discover button reports that no search provider is configured; adding URLs directly always works.

Add a whole new topic

A topic (a domain) is a folder. Creating one takes a minute and needs no code:

uv run kp domains new sql-server --name "SQL Server"

This creates domains/sql-server/ with three files to edit in any text editor:

FileWhat you write there
plugin.yamlA short description of the topic, its taxonomy (the outline of sub-topics facts get filed under), terminology (canonical names and abbreviations), and optional hints for the extractor.
sources.yamlThe starting list of websites, each with a trust level and crawl limits — the same fields as the Add your own URL form.
evaluation.yamlOptional test questions with expected answers, used to measure quality over time.

Then load it and start collecting:

uv run kp domains sync sql-server
uv run kp run pipeline sql-server --max-pages 10

Press Reload plugins on the Domains page and the new topic appears in the sidebar selector. From then on you can add URLs and keywords to it from the UI exactly like Power BI. Advanced users can add a plugin.py with custom validators (e.g. a syntax checker for the topic's language); the built-in Power BI plugin shows how.

Reading a knowledge item

Click any row in Knowledge to open the detail drawer. From top to bottom:

  • Status chip — where the item is in its life: EXTRACTED just produced · CANDIDATE passed basic checks · SUPPORTED has evidence from one source · VERIFIED from an authoritative source, or confirmed by several sources, a validator, or you · CONFLICTED another item disagrees · STALE the page it came from changed and the quote is gone · REJECTED / SUPERSEDED retired.
  • Statement — one self-contained sentence, plus a longer explanation and any code sample.
  • Confidence bar and level — confidence (0–100 %) is computed from named factors shown under Why this score: source authority, verified evidence, agreement between sources, specificity, taxonomy match and domain validation. The L0–L5 level says how it was verified (L2 = authoritative source, L3 = several independent sources, L4 = passed a validator, L5 = approved by a person).
  • Evidence — the exact quote from the page, marked verbatim when it was found word-for-word, with a link to the page. Validator results and human approvals appear here too.
  • Lifecycle — every status change with who or what made it and why. Nothing here can be edited; it is the audit trail.
  • Provenance — which extractor and model produced the item, content hash, embedding model, dates.

Reviewing & conflicts

The Review page lists open conflicts. Each shows the two statements side by side with their sources and confidence. Choose Keep A, Keep B, Both valid (e.g. they apply to different product versions), or Reject both. Your decision is recorded on both items.

Inside any item's drawer you can also Approve (raises it to level 5 and records you as evidence), Reject (retires this version), Mark stale, or Reopen. Add a short reason — it goes into the audit trail.

Asking questions

On Search & Ask, type a question and press Enter. The answer cites items as [1], [2]…; click a citation or a card on the right to open that item and inspect its evidence. Items that were retrieved but not used are shown dimmed so you can see what the assistant considered.

If the answer says the knowledge base does not cover the question, that is the intended behaviour: add a source that does, crawl it, and ask again.

Self-evaluation

The Evaluation page runs the domain's golden questions against the current knowledge base. For each question the platform retrieves, answers, then applies explainable checks (required concepts present, every citation resolves to an item with verified evidence, correct abstention when the knowledge base does not cover the question, stale or conflicting items flagged, version mentioned, validators passed) and asks a judge model whether the answer matches the reference and stays within its citations. A question passes only when both agree.

  • Run evaluation starts a run in the background; results appear per question.
  • Each run is compared with the previous run on the same question-set version. A drop in accuracy or citation correctness shows a red regression banner and a badge in the sidebar.
  • Failure analysis groups failures by cause (no citations, authoritative source not retrieved, hallucination…) with a suggested action. The platform never edits knowledge on its own — you act on the findings.
  • Runs also start automatically after a pipeline run that produced knowledge, and once a day while the app is running.
Low scores early on are normal and honest: most questions abstain until their sources have been crawled. Watch the trend, not the first number.

Choosing models (local or API)

Open Settings. The platform uses a model for three roles — triage (cheap filtering), extraction (reads every section) and reasoning & answers (contradiction checks, answers, the evaluation judge) — plus an embedding model for search. Each can be local or remote:

  1. Pick a provider card: Ollama (local), OpenAI-compatible API (OpenAI, Gemini, Groq, OpenRouter, Mistral, LM Studio…) or Anthropic API. For API providers paste the key; it is stored masked on this machine only.
  2. Press Load models — the list comes live from the provider (for Ollama: what is installed on your PC).
  3. Choose a model per role and press the tick to test it: the platform sends a tiny structured request and reports the latency. A model that is too large for your GPU shows up here as very slow.
  4. Save. New jobs use the new models immediately; the sidebar shows the active extraction model.
Changing the embedding model makes existing items invisible to search until you press Re-embed now (vectors from different models are never mixed). The page shows how many items need it.

Exporting knowledge (Canonical Knowledge Snapshots)

Snapshots (or the Export knowledge button on Domains) builds a versioned, self-contained package of everything the platform currently believes about a topic — for another AI system, a RAG pipeline, or simply to keep a dated copy.

  1. Press Export knowledge. The build runs in the background and appears as vN when ready.
  2. Open the version to see counts, the models and rule versions that produced it, and the quality gate result.
  3. Download zip for the whole package, or open individual files. For an AI system, start with ai/knowledge.jsonl (one record per fact with text and citations) or ai/knowledge.md.
  4. Verify integrity recomputes every file hash; the manifest's integrity hash identifies the snapshot.
The snapshot is not the source of truth — the original documentation is. Every record carries citations back to it, plus status and verification level, so a consumer can decide how much to trust each fact. Unchanged knowledge always produces the same hash, so two people exporting the same state get identical files.

Keeping knowledge fresh

  • Every source has a re-check interval (weekly by default). Once you have crawled a source at least once, the built-in scheduler re-checks it automatically while kp serve is running.
  • Unchanged pages are skipped cheaply (the site is asked "changed since last time?").
  • When a page changes, only the changed sections are re-read. Facts whose quote disappeared become STALE and show up on the Review page; new facts are added as usual.
  • Nothing is deleted or overwritten: old versions remain in the audit trail.

Troubleshooting

SymptomWhat to do
Sidebar says Database offlineDocker Desktop is not running or the container is stopped: docker compose up -d postgres.
Sidebar shows an amber dot next to the modelOllama is not running or the model is missing: start Ollama, then ollama pull qwen3:8b and ollama pull nomic-embed-text.
Extraction is slowNormal: a local model reads every section. Reduce max pages, or choose a smaller model in .env (KP_LLM_MODEL_EXTRACT).
A source shows BLOCKEDThe site's robots.txt forbids crawling that URL. Choose a different entry page or a source that permits it.
A job is DEAD on the Pipeline pageIt failed three times; the last error is shown. Fix the cause (usually network or model) and press retry.
Port already in useChange KP_API_PORT in .env (default 8010).
Web discovery says no search providerRun docker compose --profile discovery up -d to start the local search engine.

Glossary

DomainA topic plugin (Power BI, SQL Server…): taxonomy, terminology, sources, tests.
SourceA website the platform is allowed to read, with a trust level and crawl limits.
DocumentOne collected page (or PDF) at a point in time.
Knowledge itemOne atomic fact with evidence, confidence, status and history.
EvidenceA verbatim quote from a document, a validator result, or a human approval.
ConflictTwo items that disagree about the same thing; resolved by a person.
Run / jobA batch of background work (crawl, extract, discover) and its individual steps.
AuthorityHow much a source is trusted (0–100); part of every item's confidence.
